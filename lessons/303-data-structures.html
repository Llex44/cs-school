How a hash table knows where to look

A hash function turns a key, like a song title or an id, into a number, and that number picks a bucket. Here the function adds up the letter codes and keeps the remainder after dividing by 8. The same title always gives the same bucket, so finding it later means doing the math again and looking in one place.

When two keys land in the same bucket, that's a collision. The table just checks the few songs in that bucket. With enough buckets they stay tiny, so a lookup takes about the same time with 10 songs or 10 million.

In JavaScript, a list is an array [ ]. Hash tables are objects { }, Map and Set. In Python they're called dictionaries. When an AI says "I'll use a hash map" or "a dictionary", this is what it means.

Under the hood: real hash functions optional

Adding letter codes is too simple for real use: "Low Tide" and "Tide Low" would always collide. Real hash functions scramble every bit of the key, so similar keys land far apart.

When buckets get crowded, the table doubles its number of buckets and re-files every key. That's occasional extra work that keeps lookups fast.

Keys must match exactly. "Blue Hour" and "blue hour" hash to different buckets, which is why AI code often lowercases emails before storing or looking them up.

Where you'll meet these shapes

Stacks power undo, the Back button, and the way a program remembers which function called which (that's the "stack" in "stack trace"). Queues hold jobs waiting their turn: songs up next, emails to send, background tasks. Trees are folders, comment threads, menus, JSON and the HTML of every web page. Graphs are friends, followers, links between pages, and routes between places.

Under the hood: how graphs are stored optional

A graph is usually stored as a hash table from each item to a list of its neighbours: { "Juno Vale": ["Kite Club", "Paper Boats"], … }. Finding a shortest path means exploring neighbours in rings: first everyone 1 link away, then 2 links away, and so on. That's called breadth-first search.

A tree is a graph with rules: one top, every item has exactly one parent, and no loops. Those rules are what make folders easy to navigate.
