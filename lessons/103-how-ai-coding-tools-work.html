What's really going on

Tokens, not words
A token is a common chunk of text: a word, part of a word, or a symbol. In English one token is roughly three quarters of a word. Prices and limits for AI tools are counted in tokens.
Predict, add, repeat
At each step the model scores every token in its vocabulary (tens of thousands of them), one is picked and added to the text, and it goes again. A whole file is thousands of these steps.
Patterns, not facts
The scores come from training on enormous amounts of text and code. The model learned what usually follows what. It has no list of true facts to check, so a fluent answer isn't necessarily a correct one.
A little randomness
Tools usually sample with some randomness (temperature) so answers aren't robotic. That's why asking the same thing twice can give two different answers.
Under the hood: what this toy leaves out optional

This is a simplification. A real model weighs the entire text so far, using billions of learned numbers, to score its whole vocabulary at every step. Chat models are then trained further to follow instructions and hold a conversation. The core loop is real, though: predict one token, add it, repeat.

The tokenizer here uses a small made-up vocabulary, so its splits and numbers are illustrative. Every real model family has its own tokenizer, and the same sentence can be a different number of tokens in each.

Some models "think" before answering: they write out reasoning tokens first, then the answer. It's the same token-by-token prediction, with more room to work things out.

What the AI can see

The model has no memory of its own. Each reply is predicted from what's in its context window right now: the tool's instructions, your conversation, and any files or command output it has been given. The window is large, but it has a limit.

Big, but finite
Real windows are far bigger than this toy, often 200,000 tokens or more, hundreds of pages. But a large codebase, long error logs and a long chat still fill them.
When it's full, details go
Tools handle a full window differently: some drop the oldest messages, some summarize them. Either way, specifics like "8% tax" can quietly disappear.
Gaps get filled with guesses
When the answer isn't in the window, the model still predicts something likely. That's where a confident, wrong answer comes from.
More isn't always better
Stuffing in every file crowds out what matters and gives the model more to get distracted by. Give it what the task needs.

How agents get facts: tools

An agent is an AI that can use tools: read files, search, run commands and tests. Each tool's result lands in its context window. That's how it swaps guesses for facts, including catching its own mistakes. Step through one.

An agent at work on Bea's menu

Under the hood: invented packages are a security risk optional

Models sometimes invent package names that sound right. Attackers have noticed: they publish real packages under names AIs tend to invent, filled with harmful code. This is sometimes called "slopsquatting".

So an invented package that fails to install, like the one above, is the lucky case. Before adding any package an AI suggests, check that it's the real, well-known one. You'll learn more in 204 (dependencies) and 207 (security).

    Five quick questions. Each answer explains itself.

    Key terms

    What the words mean, and what to do about them.

    Language model
    The engine inside AI tools. It predicts likely next tokens, based on patterns learned from huge amounts of text and code.
    Token
    A chunk of text: a word, part of a word, or a symbol. Limits and prices are counted in tokens.
    Temperature
    How much randomness goes into picking each token. Higher means more varied answers.
    Context window
    Everything the model can see for this reply. Big but finite. What's not in it, the model can't know.
    Hallucination
    A confident answer that isn't true, like an invented function, package or column name. Ask for evidence: docs, a file, a test run.
    Agent and tools
    An AI that can read files, run commands and tests. Tool results go into its context, turning guesses into facts.
    A good prompt
    The goal, the relevant files, the constraints, and how to check the result.
    Fresh chat
    When a session gets long or confused, start over with a short summary of the rules and files that matter.
