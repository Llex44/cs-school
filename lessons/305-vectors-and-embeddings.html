Theory elective · Course 305 · Vectors & embeddings

To an AI, every meaning is a place on a map.

An embedding turns a word, a sentence or a whole document into a list of numbers: a point in space. Similar meanings land close together, so a computer can measure how related two ideas are. It's how AI search finds "puppy" when you type "dog".

Under the hood: cosine similarity optional

Draw an arrow from the center of the map to each point. Cosine similarity measures the angle between two arrows and ignores their length: 1 means the same direction, 0 means at right angles, −1 means opposite.

cosine(a, b) = (a₁×b₁ + a₂×b₂ + …) ÷ (length of a × length of b)

The top part, multiplying matching numbers and adding them up, is called the dot product. Dividing by the lengths makes long and short arrows comparable. You'll write this in part 3.

This toy map is flat, so unrelated words can point in opposite directions. In real models, unrelated texts usually score a little above zero rather than below, and each model has its own typical range. Compare scores from the same model, as a ranking.

A vector is just a list of numbers

On this map every word is two numbers, its position across and up. That pair is its vector, like puppy → [0.65, 0.63]. Measuring meaning is now arithmetic: close points, or arrows pointing the same way, mean related ideas.

Two numbers can only hold a little meaning. Real embedding models use hundreds or thousands of numbers per text, often 384, 768, 1,536 or 3,072. Nobody can picture that many directions, but the math is exactly the same: distance and angle work in any number of dimensions.

embed("puppy crate mattress") → [0.021, −0.113, 0.087, 0.004, … 1,536 numbers in all]

Those numbers don't come with labels. The model learned them by reading huge amounts of text, and no single number means "dog" or "furry". Only the pattern as a whole carries meaning.

The famous example is king − man + woman ≈ queen. It's real, but it's tidier than the truth. It worked for some examples in older word-embedding models, the answer is usually "the closest word that isn't one of the inputs", it fails often, and it can repeat stereotypes from the text the model learned from. Under the hood: how this toy model works optional

Our model knows about 160 words, and gives each one ten numbers with names like "dog", "food" and "delivery". A text's vector is the average of its known words, scaled to length 1. Averaging word vectors was a real early technique.

Modern embedding models read the whole text at once, so word order and context count: "dog bites man" and "man bites dog" get different vectors. They also give a vector to any text at all, including words they've never seen.

The map is flattened from ten dimensions to two so you can see it, which squashes some distances. The scores in the list are the true ones.

Meaning, keywords, or both

Keyword search looks for the same words. It's fast, exact and predictable, perfect for product codes, names and error messages. But it can't know that "dog bed" and "puppy crate mattress" mean nearly the same thing.

Semantic search compares embeddings, so it matches meaning even when no words are shared. It's fuzzier with exact strings like codes and order numbers. Many real systems run both and merge the results, called hybrid search.

The article vectors are usually kept in a vector database, which is built to find the nearest vectors among millions quickly (see course 205).

    Under the hood: real vector search optional

    With a few articles you can compare the query with every one, as your code does. With millions, that's too slow, so vector databases use clever indexes that find nearly the closest vectors much faster. It's called approximate nearest neighbor search.

    Many embedding models return vectors that already have length 1. Then cosine similarity and the plain dot product give the same ranking, and systems often skip the division.

    Check your understanding

    Five quick questions. Each answer explains itself.

    Key terms

    The words you'll hear when an AI tool sets up search, memory or RAG.

    Vector
    A list of numbers. Read as coordinates, it's a point or an arrow in space.
    Embedding
    A vector made from text (or images, or sound) by a model, so that similar meanings get nearby vectors.
    Dimensions
    How many numbers are in each vector. Real embeddings have hundreds or thousands.
    Cosine similarity
    How closely two vectors point the same way: 1 is the same direction, 0 is unrelated.
    Semantic search
    Finding texts whose embeddings are closest to the query's embedding: search by meaning.
    Keyword search
    Finding texts that contain the same words. Best for codes, names and exact phrases.
    Hybrid search
    Running keyword and semantic search together and merging the results.
    Chunk
    A piece of a longer document, embedded on its own. Good chunks hold one complete idea.
    RAG
    Retrieval-augmented generation: find the closest chunks, put them in the prompt, then let the AI answer from them.
    Vector database
    A store built to find the nearest vectors among millions, fast.
