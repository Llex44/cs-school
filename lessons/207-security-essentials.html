Authentication vs authorization

Authentication asks "who are you?" (logging in). Authorization asks "are you allowed to do this?" (permission checks). The note you read in part 1 failed the second one: you were logged in as yourself, but nothing checked that note 7 was yours. Sort each request.

Under the hood: hashing, salting and "slow" hashes optional

A hash is a one-way scramble: easy to compute forwards, practically impossible to reverse. To check a login, you hash what the user typed and compare it to the stored hash. You never need the real password back.

A salt is a random value mixed in per user, so two people with the same password get different hashes, and attackers can't precompute a giant lookup table. Password hashes (bcrypt, argon2, scrypt) are deliberately slow, which barely matters for one login but makes mass guessing painfully expensive.

Least privilege: hand out the narrowest key

    Cheat sheet

    The holes AI-written code leaves most often, how to spot them, and what to ask for.

    The holeWhat it looks likeAsk the AI for
    Leaked secretAn API key or password sitting in frontend code or in git."Move it to a server environment variable and rotate the exposed one."
    Missing authorizationYou can change an ID in the URL and see someone else's data."Check that the logged-in user owns this record before returning it."
    SQL injectionUser input glued straight into a database query."Use a parameterized query so input can never be run as a command."
    Plain-text passwordsPasswords stored as-is, or logged."Hash passwords with bcrypt or argon2, and never log them."
    Too much accessOne all-powerful key or admin login used everywhere."Give this the narrowest permissions that still work."
    Sensitive data in logsFull card numbers, tokens or passwords printed to logs."Redact secrets and PII from logs."
    CORS set to *The API accepts requests from any website."Allow only our own domains, not *."
    Old dependenciesPackages with known vulnerabilities. See course 204."Run an audit and update the flagged packages."
    The one habit that matters most. Treat every input from outside, from users, other apps or the internet, as untrusted until you've checked it. Most holes in this lesson are the same mistake: trusting something that arrived from outside.
