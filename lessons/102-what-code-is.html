What you just saw

A program runs one line at a time, top to bottom.
Each line finishes before the next one starts. In part 2 you'll see the three ways code can skip or repeat lines.
A variable is a labeled box.
let cookies = 3; makes a box, labels it cookies, and puts 3 inside. Later lines use the name to get the value back.
In code, = means "put into".
It doesn't mean "is equal to" like in math. The right side is worked out first, then stored in the box on the left. That's why cookies = cookies + 1 makes sense.
Values come in types.
Numbers like 2, text in quotes like "Total: $" (programmers call it a string), true and false, and lists in square brackets. The type decides what you can do with it.
Under the hood: why "2" + 1 is "21" optional

In JavaScript, + does two jobs. With two numbers it adds: 2 + 1 is 3. If either side is text, it glues them together: "2" + 1 is "21". That's how "Total: $" + total builds a message.

It's also a classic bug. If a number arrives as text (from a form, say), adding to it quietly glues instead of adding. Nothing crashes, the answer is just wrong. When you see strange totals, ask the AI whether a number is really text.

console.log is how a program prints. In a real website the output goes to the browser's developer console, and on a server it goes to the server's logs.

Pick a program

The four building blocks

Almost every program is made of these. When the AI hands you code, look for them, and check the thing that usually goes wrong.

Variables

let total = 0;

A named box for a value. Names are how code stays readable.

Check: do the names say what's inside? total is clear. x2 is not.

Conditions

if (stamps >= 10) { … } else { … }

Run some lines only when a test is true, and others when it's false.

Check the edges: > 10 and >= 10 differ at exactly 10.

Loops

for (let item of order) { … }

Repeat lines once for each item in a list, or until something is true.

Check: what does it loop over? Could that be empty, or a million items? Does it always end?

Functions

function priceFor(size) { … return 3; }

A named recipe: inputs go in, an answer comes back with return.

Check: does the name match what it does? One clear job per function.

How to read code you didn't write

  1. Skim the names first. Variable and function names tell you what the code is about before you read a single line closely.
  2. Find where it starts. Function definitions wait until they're called. The lines outside them run first, top to bottom.
  3. Follow one example. Pick a value, like 12 cookies, and track the boxes line by line, exactly like the visualiser does.
  4. Say it in one sentence. "This gives a free croissant when the card reaches 10." If you can't, ask the AI to explain that part, then check its answer by running an example.

    Key terms

    The words you'll hear when an AI explains its code.

    Program
    A list of instructions the computer runs one line at a time, top to bottom.
    Variable
    A named box holding one value. let makes a new one.
    = (assignment)
    "Put the right side into the box on the left." Not "is equal to".
    String, number, boolean, list
    Types of values: text in quotes, numbers, true or false, and several values in square brackets.
    if / else
    Runs one block of lines when a test is true, another when it's false.
    Comparison
    === exactly equal, > more than, >= at least. Check the edges.
    Loop
    Repeats a block of lines, for example once for each item in a list.
    Function
    A named recipe. Defining it saves it; calling it, like priceFor("large"), runs it.
    return
    Hands an answer back to the line that called the function, and ends the function.
    Error message
    The kind of problem, plus the name or line it tripped on. Read it before asking for a fix.
