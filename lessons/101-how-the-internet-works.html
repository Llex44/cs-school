What just happened

Every web page you have ever opened took these four steps. So does every app that talks to a server.

1
Look up the address (DNS)
Computers find each other by number, an IP address like 203.0.113.42. DNS is the internet's address book: it turns the name into the number. Your browser remembers the answer for a while, which is why the second page skipped this step. When the AI says "the domain doesn't resolve", this step failed.
2
Send a request
Your browser, the client, sends a short message: GET /menu, "please give me the page at /menu". It travels in small pieces called packets, hopping between routers. "Connection timed out" means nothing answered.
3
The server responds
A server is just a computer that waits for requests and answers them. Its response starts with a status code (200 means "here you go") and then the page itself. You'll meet the other codes in part 2.
4
The browser builds the page
The page arrives as HTML (the content), which asks for CSS (the looks) and JavaScript (the behavior). The browser fetches those too, then draws everything. A page with no styling usually means the CSS failed to load.
Under the hood: packets, routers and HTTPS optional

Nothing travels as one big piece. Your request and the server's response are chopped into packets of about 1,500 bytes, each labeled with where it's going. Routers pass each packet one hop closer, and different packets can take different routes. The receiving computer puts them back in order.

The https at the start of an address means the connection is encrypted. Before the request is sent, the browser and server agree on a secret key (the "TLS handshake"), so routers along the way can carry the packets but can't read them. The padlock in the address bar tells you this worked.

Real DNS has more layers too: your computer asks a resolver (often run by your internet provider), which may ask several other DNS servers before it finds the answer. Every level remembers answers for a set time, called the TTL.

What "the server is down" really means

People say "down" for all of the failures you just caused. But the fix depends completely on which step broke. A missing DNS record has nothing to do with your code, and a 500 error has nothing to do with your domain name. Before you let anyone (or any AI) start fixing, find the step that failed.

    Cheat sheet

    The words and commands you'll hear most when an AI talks about websites.

    TermIn plain wordsWhen the AI says…
    Client / serverThe client (your browser or app) asks. The server (a computer somewhere) answers."The client sends a request to the backend server."
    DNSThe internet's address book. Turns beasbakery.com into an IP address."The domain doesn't resolve." DNS can't find it.
    IP addressA computer's number on the internet, like 203.0.113.42."Point the A record at your server's IP."
    Request / responseThe question the browser sends, and the answer that comes back."The request returned a 500."
    2xx, 3xxIt worked (200), or it's somewhere else now (301)."Add a 301 redirect so old links keep working."
    4xxThe request had a problem: 404 not found, 401 not logged in, 403 not allowed."It's a 404." The server is fine; check the address.
    5xxThe server had a problem: 500 crashed, 503 overloaded."It's a 500." Ask to see the server logs.
    localhostThis computer. Nobody else can open it."It's running on localhost:3000." Not live yet.
    ping / nslookupIs the machine reachable? What's the address behind this name?"Let me check whether the domain resolves."
    curl -IFetch a URL and show only the status code and headers."curl shows a 301 to the new page, so the redirect works."
