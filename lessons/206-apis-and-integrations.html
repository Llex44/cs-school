Requests and responses

An API (application programming interface) is how one program asks another for something. Your app is the customer, the API is the waiter, and the other company's server is the kitchen you never get to see.

YouCan our party app let people order a cake from Sunny Bakery?

Under the hood: JSON optional

Most APIs speak JSON, a plain-text format for data. Curly braces hold named values, square brackets hold lists, and text goes in double quotes: {"name": "Lemon drizzle", "price": 18}.

When an AI says "the API returns JSON", it means your code gets text like this and turns it into data it can use.

What the waiter understands

Every request has a method (what you want done) and an address (what you want it done to). Every response starts with a status code, a three-digit number that says how it went. The first digit tells you whose problem it is.

MethodMeans
GETRead something. Never changes anything.
POSTCreate something new, like an order.
PUT / PATCHChange something that exists.
DELETERemove something, like cancelling an order.
StatusMeans
2xxIt worked. 200 OK, 201 Created.
4xxYour request was wrong. Fix it before trying again. 400, 401, 404, 429.
5xxTheir server failed. Not your fault. Wait and retry. 500, 503.

Keys, limits and callbacks

Real APIs want to know who's asking, limit how often you can ask, and can tap you on the shoulder when something happens. Build a request yourself and meet all three.

Your task

  1. Ask the API for its cakes, and read the error.
  2. Add your API key and try again.
  3. Order a cake with POST and a JSON body.
  4. Send requests until you hit the rate limit.
  5. Replace polling with a webhook, then catch a fake one.

Build a request

Method
https://api.sunnybakery.example/v1
Headers
Authorization: Bearer sk_test_7f3a9c21
Content-Type: application/json

GET and DELETE requests don't carry a body. Everything they need is in the address.

Response
Build a request, then press Send.
    Start simple: the method is GET and the address is /cakes. Press Send request.

    Rate limit: 5 requests per 20 seconds

    Only requests with a valid key count.

    An API key is like a membership card: a long secret string that tells the API who is asking, so it can bill you, limit you, and block you if needed. That's why it goes in a header on every request, and why it must stay secret. Part 4 shows where AI tools tend to leak it.

    Under the hood: headers and "Bearer" optional

    Headers are labelled notes attached to a request or response, like Content-Type: application/json ("the body is JSON"). Authorization: Bearer <key> means "whoever bears this key is allowed in".

    Responses have headers too. Retry-After: 12 on a 429 tells you how many seconds to wait. Good code reads it instead of guessing.

    Try it: talk to an API with curl

    curl is a command-line tool for sending requests. AI tools use it constantly to test APIs, and API docs show examples in it. This practice terminal talks to a pretend Sunny Bakery. Nothing here is real.

    Your mission

    Order a chocolate fudge cake for a party, the way your app will do it behind the scenes.

      Sunny Bakery API docs

      GET/cakeslist cakes
      GET/cakes/{id}one cake
      POST/ordersorder a cake
      GET/orders/{id}check an order
      DELETE/orders/{id}cancel it
      Base URL https://api.sunnybakery.example/v1 Auth header Authorization: Bearer <key> Order body {"cake_id": 2, "quantity": 1} Rate limit 60 requests a minute

      Reading a curl command

      curl -X POST \ -H "Authorization: Bearer $BAKERY_KEY" \ -H "Content-Type: application/json" \ -d '{"cake_id": 2}' \ https://api.sunnybakery.example/v1/orders
      -X POSTthe method (GET if you leave it out)
      -H "…"a header. Add as many as you need.
      -d '…'the body, often JSON
      -ialso show the status line and headers
