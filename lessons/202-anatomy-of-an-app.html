Core curriculum · Course 202 · Anatomy of an app

Every app is a layer cake. Customers only see the top.

The page you tap is just the top layer. Under it sit your server's code, the database that remembers everything, and the hosting that keeps it online. Learn to tell the layers apart, and you'll know where every piece of code belongs, and where secrets must never go.

Under the hood: full-stack frameworks optional

Next.js, Remix, Nuxt and SvelteKit are full-stack frameworks: frontend and backend live in one project and go online together. The layers are still there. You tell them apart by folder (in Next.js, app/api/ is backend) and by markers inside files, like 'use client'.

Other projects keep them apart, in folders like client/ and server/, or even in separate repositories. You'll explore a real-looking Next.js project in part 3.

      Only you can read it

        Why secrets can't live in the frontend. Everything the frontend uses is downloaded to the customer's device. They can press View source, open the developer tools, or watch the network, and read all of it. Squashing the code into one unreadable-looking line ("minifying") doesn't hide it. If a secret key is in the browser, it's public.

        Under the hood: environment variables optional

        Secrets live in environment variables: settings stored on the server, outside your code. On your laptop they sit in a file like .env.local. In production you type them into your hosting dashboard.

        In Next.js, a variable whose name starts with NEXT_PUBLIC_ is copied into the browser code on purpose, so never give a secret that prefix. Vite uses VITE_ the same way. Course 207 Security essentials goes further.

        Under the hood: domains, DNS and CDNs optional

        A domain like rosiesbakery.com is a name you rent each year. DNS, the internet's phone book, turns that name into the address of your host's computers.

        A CDN (content delivery network) keeps copies of your frontend files, like pages, photos and code, in data centers around the world, so a customer in Sydney doesn't wait for a server in London. Course 209 Shipping & running software covers going live.

          Under the hood: why page.tsx can run in two places optional

          In Next.js, page files are drawn on the server first by default, so the page arrives ready to show. Only files marked 'use client', and the files they import, are also sent to the browser to handle clicks and typing.

          A rule of thumb that works: anything that draws the page is frontend, anything under app/api/ is backend, and secrets only ever appear in backend code.
